## 1. MemGPT（arXiv:2310.08560，D23）

- **一句话**：把 LLM 的上下文窗口当成"主存（RAM）"，把外部存储当成"磁盘"，让模型自己管理分页（换入/换出）。
- **记忆机制**：主上下文（系统指令 + 工作记忆）↔ 外部上下文（长期记忆库）；LLM 通过函数调用做内存管理（写入/检索/更新）。
- **可偷的设计**：①"有限的上下文 = 有限的认知资源"，记忆必须取舍；②写入/检索是显式动作，而不是把一切自动塞进提示词。
- **局限**：管理全靠 LLM 自己决定，可能漏记/记错；**没有验证机制**——这正是你 write gate 的机会。

## 2. Generative Agents（arXiv:2304.03442，D24）

- **一句话**：25 个 Agent 在小镇里生活，靠"记忆流 + 反思 + 计划"产生可信的长期行为。
- **记忆机制**：记忆流（所有经历原文存下）→ 检索打分 = **recency + importance + relevance**（α 加权）→ 反思：定期把高阶观察综合成更高层记忆。
- **可偷的设计**：①检索三要素打分（D31 的混合检索直接用）；②反思 = 记忆压缩（把琐碎对话提炼成"用户偏好"）。
- **局限**：记忆流无限增长，没有"验证"和"过期"——错误记忆永远留在库里。

## 3. Reflexion（arXiv:2303.11366，D24）

- **一句话**：任务失败后，让 LLM 用自然语言反思"为什么失败"，把反思写进 episodic memory，下次重试时作为上下文——"语言化的强化学习"。
- **记忆机制**：trajectory → reward → 反思（口头批评与改进建议）→ 存 episodic buffer → 下次读取。
- **可偷的设计**：①失败也是记忆（负样本）——金融场景的"错误建议"必须记；②反思要基于轨迹证据，不能空想——这与 RIVP 的 provenance 同源。
- **局限**：反思没有外部验证，可能自我强化错误——又是 write gate 的机会。

## 4. Mem0 / A-MEM / 2026 综述（D25 选 2）

- **Mem0**（arXiv:2504.19413）：给 LLM 应用加"记忆层"，把对话抽成用户偏好结构化记忆（memory extraction → ADD/UPDATE/DELETE 三种更新操作），面向多用户/多会话。
- **A-MEM**（arXiv:2502.12110）：记忆用 Zettelkasten 式互联笔记组织，Agent 动态决定新建/链接，检索时沿链接扩散。
- **综述** [Memory in the Age of AI Agents](https://arxiv.org/abs/2512.13564)：把记忆机制梳理成"写入/存储/检索/整合/遗忘"框架，与 `10-论文精读模板.md` 的七环节表对齐。

## 四篇对比表（理解正确性的试金石）

| 论文 | 记忆单元 | 写入 | 检索 | 遗忘/更新 | 验证？ |
|---|---|---|---|---|---|
| MemGPT | 外部上下文页 | LLM 函数调用 | LLM 决定 | 有 | 无 |
| Generative Agents | 记忆流 + 反思 | 全存 | recency+importance+relevance | 无（反思近似） | 无 |
| Reflexion | 反思文本 | 失败后反思 | 按任务读 | 无 | 无（自评） |
| Mem0 | 用户偏好条目 | 提取 + ADD/UPDATE/DELETE | 语义检索 | 有 | 无 |

**关键观察（D28 写进设计文档）：这四篇都没有"验证门禁"和"证据溯源"——这正是 RIVP 能带来的增量，也是你 verimem 的卖点。**
