# RIVP 论文答辩准备（WWW 2027 投稿，匿名在审）

> 论文：*RIVP: Role-Invariant Verifiable Process for Root Cause Localization in Evolving Microservice Systems*
> 目标：面试被问到任何细节都能答上；并且能把 RIVP 连接到目标岗位（Agent 记忆）。
> 用法：D7 通读时对照第 0–1 节；D13 做第 2 节"设计类"10 问；D52 做全部 30 问并录音。

## 0. 用五句话讲清楚（背下来）

1. 微服务持续演进（实例替换、版本发布、关系变化），历史诊断步骤会指向已下线的对象或不可达路径。
2. 我们把**诊断流程本身**作为记忆单元存下来：角色化查询计划（role path），而不是存"旧结论"或"旧图"。
3. 执行时用**集合式角色绑定**在当前类型图上重解析目标：唯一匹配→bind；多个→keep 并行分支；没有→prune 该分支；全断→回退默认流程。
4. 候选排序（Inspect）与事实确认（Verify）必须用**不重叠的证据源**；确认结果三态：support / contradict / unknown——**空查询结果≠否定证据**。
5. 只有被当前证据支持的流程才允许写回记忆，测试期记忆冻结。结果：两个数据集 MRR 全面超越最强基线，且对象变化越大优势越大（分层实验证明）。

## 1. 必考概念清单（自测：不看书能写出来/画出来吗？）

（完整符号表与自测卡见 `09-RIVP符号术语自测卡.md`；§3.2–3.4 逐节带读见 `07-RIVP方法带读.md`。）

- 角色签名 κ = (τ, η)：τ 对象类型，η 在有向关系中的角色
- 六个查询角色：incident.entry / service.caller / service.callee / deployment.runtime / host.node / config.version
- 三个观测角色：signal.trace / signal.metric / signal.log；四个关系：includes / calls / runs_on / observes
- 绑定规则 Eq.(1)(2)：bind（|M|=1）/ keep（|M|>1）/ prune（|M|=0）；分支中位数 3、最多 11，不随图规模爆炸
- 记忆键 k = (entry role, local relation-type set)，**不含实体名/版本/标签/下游全路径**
- K_mem = 1：只取质量最高的已验证 episode；检索只选计划，不影响候选打分
- O_I（Inspect：Trace 路径+延迟）与 O_V（Verify：Log/Metric/部署状态）划分；lineage_id 防止同一条记录进两个通道
- 时间窗：W_obs = 60s（当前证据），W_base = 300s（历史基线，不用于验证）
- 三态语义：support 需"时间有效、与候选关联的确认记录"；contradict 需"明确反对的记录"；缺失/迟到/无关联 → unknown
- write-back：write(m_t) = 1[z_t = verified]（Eq. 5）；测试期只审计不写回
- 复杂度：绑定 O(Σ_l Σ_{u∈U_{l-1}} deg_{ρ_l}(u))，排序 O(|C_t| log|C_t|)；固定输入下结构执行确定
- 指标：MRR / Recall@k(k=1,3,5,10) / macro-MRR / 1000 次 paired bootstrap / 对象变化分层（实例替换或版本更新）

## 3. 弱点清单（面试主动说，变被动为主动）

1. 只在两个公开数据集验证，服务级定位而非实例级；
2. 角色模式与谓词是**手工规则**，规模化和跨平台泛化待验证；
3. K_mem=1 的检索策略过于简单，没做记忆整合/遗忘；
4. LLM 调用成本仍高于纯统计方法，7B–14B 范围外的模型未测；
5. 与 SOP/process-memory 系统（UModel、Flow-of-Action、AMER-RCL、MetaRCA）只有机制对比、无定量对比；
6. bootstrap 重采样单元是"实例"，同一 incident 的实例共享观测，不确定性被低估的可能。

## 4. 桥接到岗位的一句话（面试必用）

> "RIVP 教会我的是：记忆的价值不在'记了什么'，而在它能不能被重新执行、能不能被独立证据验证、系统变了之后还成不成立。我把这三个原则搬到 LLM Agent 的用户记忆上做了 verimem：用户偏好/事实只有被独立证据验证才写入长期记忆；实体用角色绑定以应对产品改名/换版；并配套用户模拟器做离线评测与 sim-to-real 分析。仓库：github.com/你的ID/verimem。"
